# QQ / 微信评论推送（WordPress 插件）

版本：1.2.0。作者：[老孙](https://www.imsun.org/)。

[项目仓库](https://github.com/jkjoy/wordpress-comment-push) · [正式发行版](https://github.com/jkjoy/wordpress-comment-push/releases)

参照 `SBlog/plugins/comment-push` 实现的 WordPress 插件，通过 QQ 官方机器人与微信 iLink 通知新评论，并可在授权会话中审核、回复评论。使用 WordPress 原生评论事件、后台权限、nonce、HTTP API 和持久存储。无需安装 OpenClaw，支持 MySQL 及使用 WordPress SQLite 集成插件的站点。

## 安装与设置

1. 从 [GitHub 最新正式发行版](https://github.com/jkjoy/wordpress-comment-push/releases/latest)下载附件 **`comment-push.zip`**，安装包解压后的顶层目录为 `comment-push`。
2. 在 WordPress「插件 → 安装插件 → 上传插件」上传该 ZIP 并启用；也可解压后将 `comment-push` 目录放入 `wp-content/plugins/`。
3. 打开后台左侧顶级菜单 **评论推送**，配置需要的渠道。

| 子菜单 | 内容 |
| --- | --- |
| 通知设置 | 选择通知的评论状态、是否通知管理员评论、是否附文章链接等内容规则 |
| QQ机器人 | QQ 凭证、接收目标、Webhook 与一次性绑定、QQ 通知开关 |
| 微信连接 | 扫码登录、验证码、接收人同步与绑定、退出登录、微信通知开关 |
| 评论管理 | QQ / 微信管理开关、授权身份与管理命令说明 |
| 运行状态 | 微信接收器状态、QQ / 微信测试通知、最近发送与管理结果 |

每个设置页单独保存，仅更新本页设置，保留其他页面的配置。更换账号或绑定目标时，管理授权仍会按下文规则撤销。旧的「设置 → QQ / 微信评论推送」地址会自动跳转至新入口。

要求 WordPress 6.4+、PHP 8.0+ 和可访问官方 HTTPS 接口的网络。QQ Webhook 自动绑定与管理命令需要 PHP sodium；手填接收 ID 的发送功能不依赖 sodium。两个通知渠道和两个评论管理开关均默认关闭，升级不会自动授权已有接收人。

## 在线更新

1.2.0 起内置 GitHub Releases 更新检查，无需在 WordPress.org 插件目录上架。插件通过 GitHub 公开 API 获取本仓库最新正式发行版，使用其固定附件 `comment-push.zip` 升级，不需要 GitHub 登录或访问令牌。

已安装 1.2.0 或更新版本后，新正式版本会出现在 WordPress「插件 → 已安装插件」及「仪表盘 → 更新」中，可直接使用原生升级操作。也可在插件列表为本插件选择「启用自动更新」，由 WordPress 按自身更新计划安装后续版本。

**1.1.1 及更早版本本身没有更新器，需要先手动安装 1.2.0 一次。** 下载 `comment-push.zip`，在「上传插件」中选择替换已安装版本，保留原有配置；完成后即可使用后续在线升级。

成功的发行版检查缓存约 6 小时，检查失败仅短暂缓存。需要立即获取发行信息时，可在「仪表盘 → 更新」重新检查更新，以刷新本插件的检查结果。临时访问 GitHub 失败不会影响评论通知和管理。

更新检查只读取公开发行版信息，升级时从 GitHub 下载安装包，不上传评论内容、QQ / 微信凭据或会话内容。

## QQ 官方机器人

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，取得 AppID 和 AppSecret，并开通目标场景权限。
2. 打开「评论推送 → QQ机器人」，填写凭证，选择私聊、QQ群或频道，先保存设置。
3. 填写接收 ID，或按下文完成自动绑定。私聊使用用户 OpenID，群聊使用群 OpenID，频道使用子频道 ID；不能填写普通 QQ 号或群号。
4. 在「QQ机器人」勾选「启用 QQ 评论通知」并保存，再到「评论推送 → 运行状态」发送 QQ 测试。

AppSecret 输入框始终留空；留空保存会保留已有密钥，也可勾选清除。改变 AppID 或 AppSecret 会清除对应访问凭证、绑定码和回调状态。更换凭证、接收类型或接收 ID 会撤销原 QQ 评论管理授权。

### Webhook 自动绑定

在「评论推送 → QQ机器人」复制实际显示的回调地址，在 QQ 开放平台完成 Webhook 验证。路径为 `/wp-json/comment-push/v1/qq/webhook`；使用普通固定链接时，以后台生成的完整地址为准。

私聊订阅 `C2C_MESSAGE_CREATE`，群聊订阅 `GROUP_AT_MESSAGE_CREATE`。生成绑定码后，在目标会话发送完整的 `绑定通知 CODE` 命令；群聊需先 @机器人。绑定码有效期为 10 分钟，只可使用一次。回到后台刷新状态，确认接收 ID 后再启用通知。自动绑定不会自动启用通知或评论管理。频道接收 ID 需手动填写。

群聊绑定会同时登记发送绑定命令的 QQ 账号为管理人；其他群成员不能管理评论。若此前仅绑定群 ID，须由需要管理评论的账号重新发送新生成的绑定命令，确认后台显示群管理人 ID 后再启用管理。

**QQ 平台必须能访问公网 HTTPS 回调地址。** `localhost` 或 `127.0.0.1` 本地站点不能直接接收官方回调，可先手填 OpenID 测试发送。机器人还需已添加好友或已入群，接收人需允许主动消息。频道推送需要其他程序维持机器人的 WebSocket 在线。消息权限、平台审核、频率和域名白名单可能影响投递；可关闭附带文章链接后重试。

回调严格验证 QQ AppID 与 Ed25519 签名，处理绑定与已授权会话的管理命令，不保存原始事件内容。参考：[官方 Webhook 文档](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/event-emit/webhook.html)。

## 微信 iLink

1. 在「评论推送 → 微信连接」获取二维码，用微信扫码并确认；如要求验证码，在同页提交验证码。
2. 点击检查登录状态。登录后，向微信机器人发送一条消息，再在后台同步接收人。
3. 必要时从已同步的接收人列表选择绑定，勾选微信通知并保存。
4. 到「评论推送 → 运行状态」发送微信测试，检查最近结果。

二维码在管理员浏览器本地生成，不调用第三方二维码服务。后台显示接收人和上下文状态，不显示 token 或会话凭证。退出微信会清除本地凭证、接收人和会话，并关闭微信通知与评论管理；重新扫码登录也须重新绑定和授权。

微信协议移植自 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)，详情见 [第三方许可](THIRD_PARTY_NOTICES.md)。微信通知依赖平台会话规则和有效上下文；如会话过期，请重新扫码，或先给机器人发送消息再同步。接口接受请求不代表接收设备已实际收到或阅读。

## 用机器人管理评论

完成接收人绑定后，在「评论推送 → 评论管理」按需勾选「允许已绑定的 QQ 会话管理评论」或「允许已绑定的微信接收人管理评论」并保存。这两个开关与新评论通知独立，可以只接收通知、只管理评论，或同时启用。

保存时将当前 WordPress 管理员记录为授权用户，不从聊天消息或表单隐藏字段接受任意用户 ID。每条命令都检查该用户的当前权限，回复评论使用该用户身份。请在「评论管理」核对授权 WordPress 用户、QQ 管理会话/群管理人和微信接收人；关闭管理开关后，该渠道不再执行命令。

- QQ 私聊：仅接受已保存目标 OpenID 发来的管理命令；须已配置官方 Webhook。
- QQ 群聊：仅接受目标群中通过一次性绑定码登记的管理人命令，发送时须 @机器人。旧版本群绑定必须重新登记管理人。
- QQ 频道：当前仅支持通知，不支持评论管理。
- 微信：仅接受本次扫码账号已绑定的接收人命令；需要持续运行的接收器或可触发的 WP-Cron。

### 管理命令

将 `ID` 替换为通知中的评论编号，也可先发送 `待审评论` 获取编号。

| 命令 | 用途 |
| --- | --- |
| `评论帮助` | 显示命令说明 |
| `待审评论 [页码]` | 查看待审核评论；页码可省略，例如 `待审评论 2` |
| `查看评论 ID` | 查看指定评论，例如 `查看评论 123` |
| `通过评论 ID` | 设为已通过审核 |
| `驳回评论 ID` | 设为待审核 |
| `垃圾评论 ID` | 标记为垃圾评论 |
| `删除评论 ID` | 移入回收站 |
| `恢复评论 ID` | 恢复回收站中的评论 |
| `回复评论 ID 内容` | 以授权用户发表回复，例如 `回复评论 123 谢谢你的反馈。` |

命令处理结果回复到已授权会话。回复命令会创建真实的 WordPress 评论。新评论推送包含评论编号；机器人回复也遵循插件的管理员评论通知设置。

仅处理具有可信平台时间、在本次启用管理后发送且不超过 5 分钟的新命令。启用前的旧消息不执行，同一条平台消息重复投递不会重复操作。

### 微信自动接收

普通主机默认使用约每分钟一次的 WP-Cron 检查新消息。WP-Cron 依赖站点访问，没有访客时可能延后；关闭了 WordPress 自动定时任务的站点，需要外部计划任务或独立接收进程。打开或刷新设置页不会直接发起微信平台请求。

需要持续接收时，在 `wp-config.php` 加入以下设置，放在载入 `wp-settings.php` 之前：

```php
define('WPCPUSH_RECEIVER_MODE', 'worker');
```

然后在 WordPress 安装目录使用与站点相同 PHP 配置启动接收进程：

```console
php wp-content/plugins/comment-push/worker.php
```

此命令需要保持运行，生产服务器可交由现有进程管理工具维持。独立进程模式用于替代网页 WP-Cron 长轮询，适合 Windows PHP 内置服务器等 HTTP 并发受限的环境，避免接收消息时占用 HTTP 处理进程。

仅本测试站：开发目录中的 `start.ps1` 会同时启动站点和独立接收器，`stop.ps1` 会同时停止它们，无需另行安装服务或创建计划任务。这两个站点启动脚本不包含在发布的插件 ZIP 中，其他站点按自己的主机环境运行接收器。仍需先扫码、绑定并启用微信管理；未启用时不自动拉取管理消息。无需保持后台页面打开。

「评论推送 → 运行状态」中的微信命令接收状态显示接收模式、最近心跳、最近检查时间和简要结果。同页「最近管理结果」仅保留一条不含评论正文或回复原文的状态。QQ 管理命令直接通过官方 Webhook 进入，不依赖微信接收器。

## 评论行为

- 监听 `wp_insert_comment`，覆盖传统评论表单、REST 和程序写入的文章及页面评论。审核、编辑、标记垃圾评论等状态变化不会重复发送新评论通知。
- 支持待审核和直接发布的新评论，可分别开关；跳过垃圾评论、垃圾箱、pingback 和 trackback。
- 默认跳过具有 `manage_options` 权限的管理员自己发表的评论；普通登录用户的评论正常通知。
- 消息包含站点、文章、评论编号、状态、评论者和最多 400 个 Unicode 字符的摘要，可选文章链接，不附邮箱、IP 或 User-Agent。
- 两个通道独立处理，单通道失败不影响另一通道，也不会回滚已经保存的评论。不修改 WordPress 原有邮件通知。
- 评论请求内同步发送，网络故障会增加等待时间。只有 QQ HTTP 401 会刷新访问凭证并重试一次，其余发送错误不自动重发。
- 每个通道只保留最近一次发送结果，不保存通知正文或原始接口响应。

## 数据与卸载

配置、平台凭证、扫码状态、管理授权和最近结果保存在 `wpcpush_` 前缀的 WordPress options 中，关闭自动加载，不暴露为公开 REST 设置。不在插件状态中保存原始平台事件、评论正文或回复原文；回复本身按正常评论存入 WordPress。请按 WordPress 的正常方式保护和备份站点数据库。

停用插件会停止通知、自动接收和评论管理并保留配置；在 WordPress 中删除插件时，会清除其设置、凭证和状态。

## 发布新版本

维护者需要同步更新 `comment-push.php` 中的版本头和 `WPCPUSH_VERSION`、`readme.txt` 的 Stable tag，以及本说明的当前版本和更新记录。提交代码后推送对应的 `v主版本.次版本.修订版本` 标签，仓库的 GitHub Actions 会检查 PHP 8.0 语法、核对版本号、生成并发布 `comment-push.zip`。

也可在仓库根目录运行 `python tools/build-release.py` 本地打包。发行附件必须使用 `comment-push.zip` 文件名，且解压目录固定为 `comment-push/`；WordPress 更新器会检查本仓库最新正式 Release，不使用 GitHub 自动生成的 Source code 压缩包。
